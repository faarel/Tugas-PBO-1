=================================================
        RANCANGAN KELAS: HotelRoom
=================================================

+-----------------------------------------+
|              HotelRoom                   |
+-----------------------------------------+
| - nomorKamar         : String  (tetap)  |
| - tipeKamar           : String  (tetap)  |
| - kapasitasTamu       : int     (tetap)  |
| - hargaPerMalam        : double          |
| - jumlahTamuMenginap  : int              |
+-----------------------------------------+
| + checkIn(jumlahTamu)                    |
| + checkOut()                             |
| + ubahHarga(hargaBaru)                   |
| + getHargaPerMalam()                     |
| + getJumlahTamuMenginap()                |
| + tampilkan()                            |
+-----------------------------------------+

INVARIAN (aturan yang harus selalu benar selama objek hidup):

1. hargaPerMalam > 0
   Alasan: kamar hotel tidak mungkin gratis atau berharga negatif;
   ini aturan bisnis dasar, bukan sekadar validasi input.

2. 0 <= jumlahTamuMenginap <= kapasitasTamu
   Alasan: kamar tidak boleh "kelebihan tamu" (masalah keamanan &
   kenyamanan) dan jumlah tamu tidak masuk akal jika negatif.

CATATAN DESAIN:
- nomorKamar, tipeKamar, kapasitasTamu bersifat tetap (final/readonly)
  karena itu identitas fisik kamar, tidak berubah selama objek hidup.
- Tidak ada setHargaPerMalam() atau setJumlahTamuMenginap() secara
  langsung -> field ini punya invarian, jadi perubahan HARUS lewat
  method yang memvalidasi (ubahHarga, checkIn, checkOut).
- checkOut() menolak jika kamar sudah kosong -> mencegah
  jumlahTamuMenginap menjadi negatif.
